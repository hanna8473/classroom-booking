# 학교생활지원 시스템 이전 준비서

## 운영 환경 보호

전환 승인 전까지 기존 Firebase와 Netlify에 접속하거나 설정을 변경하지 않는다. 테스트는 별도 Supabase 프로젝트와 별도 GitHub Pages 주소에서 가상 데이터로 진행한다. 운영 Firebase를 참조하는 HTML 사본은 비교용으로만 보관하고 GitHub Pages에 올리거나 브라우저에서 실행하지 않는다.

기준 사본은 이 작업 공간의 `work/classroom-baseline/`에 있다. `index.html`과 `cleaning_duty_3.html`의 SHA-256 해시를 데스크톱 원본과 대조했다. 사본은 현재 운영 코드의 구조를 조사하기 위한 것이며 Netlify에 게시된 파일과의 일치 여부는 확인하지 않았다.

## 데이터와 동작 이전 범위

| Firebase 경로 | Supabase에서 보존할 동작 |
| --- | --- |
| `bookings`, `archivedBookings` | 예약 생성·취소와 과거 예약 조회. 같은 날짜·강의실·시간대에 여러 사람의 예약을 허용한다. 동시 요청에서도 각 예약을 보존하고, 같은 사람의 동일 날짜·시간대 중복 신청 및 기존 일일 한도와 특수 요일 규칙을 트랜잭션에서 확인한다. |
| `classrooms`, `gradeRoomsSeeded`, `allowedDates`, `bookingTimes`, `scheduleNotes`, `weeklyAvailability`, `baseWeeklyAvailability`, `tempAvailability`, `thursdayRule` | 교실 설정, 예약 가능 날짜와 시간, 일정 메모, 기본 및 임시 예외를 보존한다. |
| `rosterMonWed`, `rosterTueThu`, `attendanceChecks`, `activeTodayTab` | 요일별 명단, 출석 체크와 화면에서 공유하는 탭 상태를 보존한다. |
| `chromebookBookings`, `chromebookReturnPeriod`, `chromebookReturnPeriodArchive` | 크롬북 예약, 반납 정보, 반납 이력을 보존한다. `chromebookBookings/_pw`는 인증 정책으로 교체할 항목이다. |
| `bibleReading` | 사용자별 읽기 기록을 보존하고 조회·수정 권한을 확인한다. |
| `cleaningDuty` | 쿼터, 학생 명단, 구역, 요일·교실·재활용 배정, 배정 통계와 자동 배정 복구 데이터를 보존한다. 당번표의 변경은 메인 화면에도 반영되어야 한다. |
| `adminPassword` | Supabase Auth 및 행 수준 보안(RLS)으로 교체한다. 기존 비밀번호 값은 이전 대상에서 제외한다. |

Firebase 원본 JSON을 받기 전에는 실제 데이터 형태와 건수를 확정할 수 없다. 코드에는 배열과 키가 있는 객체를 모두 처리하는 경로가 있다. 이전 도구를 만들 때 키, 배열 순서, 날짜 형식, 빈 값과 삭제 처리를 확인한다. 학생과 교직원이 사용할 인증 방식 및 각 역할의 열람 범위는 운영 전환 전에 정한다.

## 구현과 검증 순서

1. 작업용 기준 사본을 바탕으로 별도 소스에서 Firebase 호출과 브라우저 비밀번호 로직을 교체한다. Supabase의 공개 키만 브라우저 코드에 사용하고, 서버 권한 키와 데이터 백업은 저장소 밖에 둔다.
2. 별도 Supabase 프로젝트에서 데이터 구조, 권한, 초기 조회 및 실시간 갱신을 구현한다. 학생 정보에 접근하는 기능은 학교에서 승인한 사용자만 접근할 수 있도록 권한을 검증한다.
3. 별도 GitHub Pages 주소에서 두 HTML의 상대 링크와 로그인 후 복귀 주소를 검증한다. 배포본에 운영 Firebase 주소, 관리자 비밀번호, 학생 정보가 포함되지 않았는지 확인한다.
4. 서로 다른 두 사람이 두 브라우저에서 같은 날짜·강의실·시간대에 동시에 신청하면, 각자 기존 신청 조건을 충족할 때 두 건 모두 저장되는지 확인한다. 같은 사람이 두 브라우저에서 같은 날짜·시간대에 동시에 신청하면, 강의실이 달라도 한 건만 저장되는지 확인한다. 기존 일일 한도와 특수 요일 예외도 확인한다. 예약 취소와 과거 예약 보관, 출석 체크, 크롬북 반납 이력, 성경 읽기 기록을 함께 검증한다. 청소 당번표의 수정·자동 배정·복구 결과는 당번표와 메인 화면에서 대조한다. 로그인 전이나 권한이 없는 계정의 데이터 접근도 확인한다.
5. 가상 데이터로 가져오기 재실행을 연습한다. 중복 없이 재시도할 수 있는지와 주요 날짜·학급별 건수 및 표본 데이터가 일치하는지 확인한다.

## 전환 승인 이후

전환 일정과 새 주소를 확정하고 최종 백업부터 실제 데이터 검증까지 필요한 쓰기 중지 시간을 합의한다. Supabase 적재와 검증이 끝나면 GitHub Pages 운영 주소를 안내한다. 전환 뒤 새로 입력된 데이터가 있다면 문제가 생겼을 때 기존 주소로 되돌리기 전에 새 데이터의 보존 및 반영 방법을 확인한다.

현재 완료된 작업은 로컬 기준 사본 생성과 코드 기준 이전 범위 조사다. Supabase 연결, GitHub Pages 배포, 실제 데이터 검증은 아직 진행하지 않았다.
